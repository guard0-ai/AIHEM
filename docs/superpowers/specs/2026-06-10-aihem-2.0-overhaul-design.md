# AIHEM 2.0 — Agent-Native Security Range (Master Design)

**Date:** 2026-06-10
**Status:** Approved (master design); sub-project specs to follow
**Author:** brainstorming session
**Supersedes:** AIHEM v1.0.0 (2024) challenge model

---

## 1. Vision

Transform AIHEM from a 2024-era "prompt-injection + SQLi" lab into a **2026 agent-native
security range**. The centerpiece becomes a real (intentionally insecure) **agent that
connects to MCP servers, uses tools, has persistent memory, and spawns sub-agents**. Most
challenges become *agent exploitation* against that surface.

Existing services are kept but re-mapped to the **2025 OWASP LLM Top 10**, and every
challenge is cross-referenced to **OWASP Agentic threats** and **MITRE ATLAS**.

### Why now (June 2026)

The current platform is ~2 years stale. It covers the 2023 OWASP LLM Top 10 and has no
coverage of the surfaces that define 2025–2026 AI security:

- The **2025 OWASP LLM Top 10** revision (system prompt leakage, vector/embedding
  weaknesses, unbounded consumption replacing model DoS, etc.).
- The **MCP attack surface** — tool poisoning, rug-pull tool updates, confused-deputy,
  prompt injection via tool descriptions/responses, token/credential theft, malicious
  servers, cross-server shadowing.
- **Agentic / autonomous-agent risks** — memory poisoning, excessive agency in multi-step
  loops, agent hijacking, multi-agent collusion, cascading hallucination, tool-chain abuse.

---

## 2. Approach decision

Three approaches to "how authentic is the agent" were considered:

- **A — Simulated/scripted agent:** cheapest, but a fake agent undercuts the point in 2026.
- **B — Real agent loop with a swappable brain (CHOSEN):** one orchestrator with a real
  ReAct/tool-calling loop, a deterministic `MockBrain` for offline/CTF reliability, and an
  `LLMBrain` for BYO-key realism. Grading keys off observable side-effects, so it is
  deterministic regardless of brain.
- **C — Always-real LLM:** most authentic but non-deterministic and requires keys
  (explicitly ruled out).

**Locked decisions:**

| Decision | Choice |
|---|---|
| Scope | Full platform + content overhaul |
| Taxonomy anchors | OWASP LLM Top 10 (2025) + OWASP Agentic threats + MCP attack surface + MITRE ATLAS (cross-ref) |
| LLM backbone | Deterministic core + optional real LLM (BYO key / local) |
| Tech foundation | Evolve current stack: Python/FastAPI microservices + Docker Compose + React |
| Agent authenticity | Approach B — real loop, swappable `MockBrain`/`LLMBrain` |

## 3. Architecture

Evolve the current FastAPI + Docker Compose + React stack. Add/realize three things; keep
the rest.

| Service | Status | Role |
|---|---|---|
| **agent-orchestrator** | NEW (replaces stub `agent-service`) | Real ReAct loop; pluggable `MockBrain`/`LLMBrain`; tool registry; planner; sub-agent delegation; acts as **MCP host** |
| **agent-memory** | NEW | Persistent, *poisonable* memory store (Redis/pg-backed) for the agent |
| **mcp-servers** (×3–4) | NEW | Real but vulnerable MCP servers: `files-mcp`, `tickets-mcp`, `notes/email-mcp`, and `third-party-mcp` (the "malicious marketplace" server) |
| **exfil-collector** | NEW | Sink service that records when secrets/tokens leave the system (used for deterministic grading) |
| rag-service | REFRESH | Vector/embedding weaknesses (LLM08-2025) |
| model-registry | REFRESH | Supply chain / model provenance (LLM03-2025) |
| chatbot-service | REFRESH | Prompt injection / system-prompt leakage (LLM01/LLM07-2025) |
| auth-service | KEEP | Identity for confused-deputy & token-theft scenarios |
| challenge-validator | UPGRADE | Side-effect–based deterministic grading (see §5) |

The **orchestrator is an MCP host**: it discovers tools from the MCP servers, so MCP-layer
attacks (poisoned tool descriptions, rug pulls, token theft) flow naturally into agent
behavior. Sub-agents are delegated tasks through the same loop, enabling multi-agent
confused-deputy and collusion scenarios.

### Component contracts (high level)

- **agent-orchestrator**: input = task + session; depends on tool registry, MCP host
  client, agent-memory, brain. Output = transcript of steps + tool calls + final answer.
- **brain interface**: `decide(state) -> action` (tool call or final answer). Two
  implementations: `MockBrain` (deterministic, rule/script-driven, *obeys* injected
  instructions by design) and `LLMBrain` (real model via provider adapter).
- **agent-memory**: `read(session)`, `write(session, entry)`, `search(query)`. Poisonable
  by design (no provenance checks).
- **mcp-server**: standard MCP tool listing + invocation; each ships an intentional flaw.
- **exfil-collector**: `POST /collect` records `{secret, source, channel}`; validator
  queries it.

## 4. Challenge catalog (the 2026 content)

~45 challenges across 8 tracks; the new MCP and agentic tracks are the headline.

1. **Prompt Injection & System Prompt** (refresh) — LLM01 / LLM07-2025
2. **MCP Exploitation** (NEW) — tool poisoning, rug-pull updates, confused-deputy,
   injection via tool *descriptions* and *responses*, OAuth/token theft via malicious
   server, cross-server tool shadowing
3. **Agentic Exploitation** (NEW) — memory poisoning, goal/instruction hijacking, excessive
   agency in multi-step loops, multi-agent collusion/confused-deputy, cascading
   hallucination, tool-chain abuse
4. **RAG / Vector & Embedding** (refresh) — LLM08-2025
5. **Supply Chain & Model Provenance** (refresh) — LLM03-2025
6. **Improper Output Handling & Downstream** (refresh) — LLM05-2025
7. **Sensitive Info Disclosure** (refresh) — LLM02-2025
8. **Unbounded Consumption** (replaces old Model DoS) — LLM10-2025

Every challenge entry in `challenges.yaml` gains three taxonomy tags: `owasp_2025`,
`agentic_threat`, and `mitre_atlas`.

## 5. Deterministic grading

The validator grades on **observable side-effects**, not LLM text:

- An **`exfil-collector`** sink records when secrets/tokens leave the system.
- **Tool-call logs** from the orchestrator show which tools fired and with what arguments.
- The **agent-memory store** is inspected for injected payloads.

This makes `MockBrain` and `LLMBrain` both produce gradable, repeatable outcomes. Text
flags (e.g. `AIH3M_...`) remain for pure text-extraction challenges.

## 6. Decomposition & build order

A full overhaul is too large for a single spec. It is split into sub-projects, each with
its own spec → plan → build cycle:

1. **Agentic core + deterministic brain** — foundation; everything depends on it.
2. **MCP attack surface** — vulnerable MCP servers + host integration.
3. **Agentic challenge track** — memory poisoning, hijacking, multi-agent, etc.
4. **Taxonomy refresh** — re-map existing services + `challenges.yaml` to 2025 OWASP.
5. **Validator / scoring v2** — side-effect grading + sink collector.
6. **Frontend + docs refresh** — new-track UI, walkthroughs, researcher guide, bump to v2.0.

**Order rationale:** sub-project 1 (agentic core) is the foundation the MCP and agentic
tracks plug into; the validator (5) can be built alongside core since grading is
side-effect based; docs/frontend (6) come last once tracks are stable.

**Next step:** brainstorm **sub-project 1 (agentic core)** in full detail.

## 7. Non-goals / YAGNI

- No production hardening — the platform is intentionally vulnerable and isolated-only.
- No bundled local model in core (BYO key or user-supplied local endpoint only).
- No rewrite to a non-Python stack.
- No unrelated refactoring of services beyond what each track requires.
- Existing safety warnings, license, and isolation guidance are preserved.
